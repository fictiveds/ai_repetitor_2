# Telegram-бот для записи к репетитору

Этот Telegram-бот предназначен для автоматизации процесса записи учеников (или их родителей) на занятия к репетитору. Бот интегрирован с Google Calendar для управления расписанием и использует LLM через OpenRouter для более естественного общения.

## Основные функции

-   **Запись на занятие**: Пользователи могут выбрать удобное время из доступных слотов.
-   **Отмена занятия**: Пользователи могут отменить ранее созданную запись.
-   **Просмотр доступных слотов**: Возможность посмотреть свободное время без немедленной записи.
-   **Гибкое общение**: Благодаря LLM, бот может отвечать на общие вопросы и обрабатывать нетипичные запросы согласно заложенной логике.
-   **Интеграция с Google Calendar**: Занятия автоматически создаются и удаляются в календаре репетитора.
-   **Уведомления администратору**: Репетитор (администратор) получает уведомления о новых записях и отменах.
-   **История диалогов**: Ведется история переписки с каждым пользователем.

## Технологии

-   Python 3.9+
-   aiogram 3.x (для Telegram Bot API)
-   Google Calendar API (google-api-python-client)
-   OpenRouter API (для интеграции с LLM)
-   FastAPI/Uvicorn (не используется напрямую в боте, но код для API календаря был предоставлен на его основе и адаптирован)

## Установка и настройка

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <URL_репозитория>
    cd <имя_папки_репозитория>
    ```

2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    python -m venv venv
    source venv/bin/activate  # для Linux/macOS
    # venv\Scripts\activate  # для Windows
    ```

3.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

4.  **Настройка Google Calendar API:**
    *   Перейдите в [Google Cloud Console](https://console.cloud.google.com/).
    *   Создайте новый проект или выберите существующий.
    *   Включите **Google Calendar API** для вашего проекта.
    *   Создайте **сервисный аккаунт**:
        *   Перейдите в "IAM & Admin" -> "Service Accounts".
        *   Нажмите "Create Service Account".
        *   Дайте ему имя (например, "telegram-bot-calendar").
        *   На шаге "Grant this service account access to project" можно не давать роли на уровне проекта, если доступ будет только к календарю.
        *   Нажмите "Done".
        *   Найдите созданный сервисный аккаунт в списке, нажмите на него.
        *   Перейдите на вкладку "Keys".
        *   Нажмите "Add Key" -> "Create new key".
        *   Выберите "JSON" и нажмите "Create". Файл JSON будет скачан на ваш компьютер. **Сохраните этот файл в надежном месте.**
    *   **Откройте доступ к вашему Google Calendar для сервисного аккаунта:**
        *   Скопируйте email сервисного аккаунта (выглядит как `что-то@ваш-проект.iam.gserviceaccount.com`).
        *   Откройте Google Calendar, к которому вы хотите дать доступ.
        *   В настройках календаря (Settings and sharing) найдите раздел "Share with specific people".
        *   Нажмите "Add people".
        *   Вставьте email сервисного аккаунта.
        *   В разделе "Permissions" выберите "Make changes to events".
        *   Нажмите "Send".

5.  **Настройка переменных окружения:**
    *   Создайте файл `.env` в корневой директории проекта, скопировав содержимое из `.env.example`.
    *   Заполните файл `.env` вашими данными:
        *   `BOT_TOKEN`: Токен вашего Telegram-бота (получить у @BotFather).
        *   `GOOGLE_CALENDAR_ID`: ID календаря, к которому вы предоставили доступ. Обычно это email адрес вашего основного календаря или специальный ID, если это дополнительный календарь (например, `your-email@gmail.com` или `xyz@group.calendar.google.com`). Чтобы его найти: Google Calendar -> Settings and sharing -> нужный календарь -> Integrate calendar -> Calendar ID.
        *   `SERVICE_ACCOUNT_FILE`: Полный путь к скачанному JSON-файлу ключа сервисного аккаунта (например, `/home/user/secrets/google_service_account.json` или `C:\Users\User\secrets\google_service_account.json`).
        *   `OPENROUTER_API_KEY`: Ваш API-ключ от OpenRouter.ai.
        *   `ADMIN_TG_ID`: Telegram ID администратора (репетитора), которому будут приходить уведомления. Можно узнать у бота @userinfobot.

6.  **Системный промпт для LLM:**
    *   Файл `system_prompt.txt` содержит основной промпт для LLM. Вы можете его отредактировать для изменения поведения или тональности ответов ассистента.

## Запуск бота

После выполнения всех шагов по установке и настройке, запустите бота командой:

```bash
python main.py
```

Бот начнет работу и будет готов принимать сообщения в Telegram.

## Структура проекта

-   `main.py`: Основной файл для запуска бота, инициализация Dispatcher.
-   `config.py`: Загрузка конфигурации из `.env`.
-   `calendar_integration.py`: Модуль для взаимодействия с Google Calendar API.
-   `llm_integration.py`: Модуль для взаимодействия с OpenRouter API.
-   `history_manager.py`: Модуль для управления историей диалогов пользователей.
-   `states.py`: Определения состояний FSM (Finite State Machine) для управления диалогами.
-   `system_prompt.txt`: Системный промпт для LLM.
-   `handlers/`: Директория с обработчиками сообщений:
    -   `common.py`: Общие обработчики (например, `/start`, `/help`).
    -   `booking.py`: Логика записи на занятия.
    -   `cancellation.py`: Логика отмены занятий.
    -   `llm_fallback_handler.py`: Обработчик для сообщений, которые передаются LLM.
-   `user_histories/`: Директория, где хранятся файлы истории диалогов (создается автоматически).
-   `requirements.txt`: Список зависимостей Python.
-   `.env.example`: Пример файла для переменных окружения.
-   `README.md`: Этот файл.

## Возможные проблемы и их решения

-   **Ошибка `FileNotFoundError` для файла сервисного аккаунта**: Убедитесь, что путь в `SERVICE_ACCOUNT_FILE` в `.env` указан корректно и файл существует.
-   **Ошибки Google Calendar API (403, 404)**:
    *   Убедитесь, что Google Calendar API включен в Google Cloud Console.
    *   Проверьте, что сервисному аккаунту предоставлены правильные права доступа ("Make changes to events") к нужному календарю.
    *   Убедитесь, что `GOOGLE_CALENDAR_ID` в `.env` указан верно.
-   **Ошибки OpenRouter API**:
    *   Проверьте правильность `OPENROUTER_API_KEY`.
    *   Убедитесь, что у вас есть доступ к выбранной модели в OpenRouter и достаточно кредитов.
-   **Бот не отвечает или падает при запуске**: Проверьте логи в консоли на наличие сообщений об ошибках. Часто это связано с неправильной конфигурацией в `.env` или отсутствием зависимостей.
